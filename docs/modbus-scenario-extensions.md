# Modbus TCP 条件联动与 Python 场景扩展

场景扩展用于本机模拟服务内的点位联动。配置属于一个 Unit ID，源点位和输出点位均限定在该站。不同从站、不同模拟服务互不串写。保留已有固定值、递增、心跳、斜坡、正弦和时间轴规则。

## 用表单配置

1. 停止服务，添加源点位 `HR / 0` 和输出点位 `HR / 10`，初始值均为 0。
2. 打开「场景模拟…」，在顶部选中目标 Unit ID，点击「新增扩展…」。
3. 在「条件联动」页选择源点位 `HR / 0`，条件为「等于」，比较值填 10。
4. 添加输出动作：`0 ms → HR / 10 = 1`、`2000 ms → 2`、`5000 ms → 3`、`8000 ms → 0`。
5. 点击「检查并预览」，确认预览中的 Unit ID、时刻和值，再点「应用扩展」。保存方案；项目模式还需保存项目文件。
6. 启动服务，再点击「启动场景」。通过客户端或本机「修改当前值」将 `HR / 0` 从 0 写为 10，观察输出序列。

动作时刻从本次触发开始计算。5000 ms 表示触发后的第 5 秒，与 2000 ms 动作间隔为 3 秒。同一时刻可设置多个不同目标，这些值整批校验后提交。正延时至少 20 ms。

每个动作的「写入方式」可选「手动填写」或「取点位值」。手动填写固定数值；取点位值可选择当前从站内的任意已配置点位，包括条件中的源点位。每个动作执行时读取该点位的当前值，再写入目标点位。例如 `HR / 0 = 10` 时触发，动作选择 `HR / 10 ← HR / 0`，就会把读取到的值写入 `HR / 10`。延时动作读取执行当时的值；同一步骤先读取所有取值点位，再整批写入。数值不符合目标类型或范围时，该步骤整体失败并停用扩展。

条件下拉框还可选择「无条件」，无需填写源点位和比较值。规则在启动场景时执行一次，并按动作时间依次执行；暂停后继续不会重放。重置后重新启动、重新启用扩展或重新启动从站时可再次执行。此模式也支持取点位值。

选中 Unit 7 时只展示该站配置；切到 Unit 8 后只展示 Unit 8。基础场景的点位下拉框也按 Unit ID 过滤。窗口内启动、暂停和重置控制**整个模拟服务**。

## 用 Python 定义序列

新增扩展后选择「Python 扩展」页。下面的代码可直接用于上述两个 UInt16 点位：

```python
from all_protocol.scenario_sdk import Scene, Step


def build(scene: Scene) -> None:
    command = scene.point("HR", 0)
    state = scene.point("HR", 10)
    scene.when_equal(
        id="startup_sequence",
        source=command,
        value=10,
        completion="hold",
    ).sequence([
        Step(at_ms=0, values={state: 1}),
        Step(at_ms=2000, values={state: 2}),
        Step(at_ms=5000, values={state: 3}),
        Step(at_ms=8000, values={state: 0}),
    ])
```

确认代码可信后勾选本机检查许可，点击「检查并预览」。检查在独立进程进行，最多 3 秒；错误包含源码位置，原已应用配置不受影响。检查通过后显示实际绑定的 Unit ID 和所有动作，应用后保存。

`scene.point()` 使用当前从站内已配置逻辑点位的起始偏移，支持 `HR`、`IR`、`Coil`、`DI`，不能传其他 Unit ID。一份 Python 定义可通过函数和循环生成多条互不争用输出的规则。浮点相等比较需明确传入 `abs_tol` 和 `rel_tol`。

Python 中，`Step(at_ms=0, values={state: command})` 表示执行时读取 `command` 并写入 `state`；`values={state: 1}` 仍表示写入固定值。无条件规则使用 `scene.always(id="copy").sequence([Step(at_ms=0, values={state: command})])`，同样只在启动场景时执行一次。

代码只在检查时执行 `build(scene)` 生成计划；服务运行期间由程序执行计划。SDK 不提供运行期回调或 `sleep`。独立进程用于隔离卡顿与崩溃，**不是安全沙箱**，只应检查自己信任的代码。检查许可按内容摘要保存在本机，不随项目导出。未获本机许可的 Python 扩展保持停用，TCP 服务和基础场景仍可使用。

## 触发、保持与恢复

- 默认只在条件从不成立进入成立时触发；持续为 10 或重复写入 10 不会连续启动。先写其他值再写 10 才能重触发。
- 启动时已经满足条件默认不触发；表单可勾选「首次启动已满足时也触发」，SDK 对应 `fire_initial=True`。
- 一次执行未完成时的新触发被忽略。条件失效默认继续执行；可勾选「条件失效时取消后续步骤」，SDK 对应 `cancel_on_false=True`。
- 默认监听客户端、本机手动值修改和基础场景的提交。扩展自身赋值及重置不会触发其他扩展。
- 扩展取得全部输出控制权后，基础规则暂停写这些输出，规则配置保留。输出已被手动接管时整次触发拒绝，不部分写入。
- 默认完成后保持最终值和输出控制权。选择「释放输出 / 恢复基础场景」后，基础规则恢复当前场景时刻的设定值；无基础规则的点保持最后值。
- 可选择完成后自动释放，SDK 对应 `completion="release"`。不同已启用规则不能声明重叠输出，检查时会拒绝。
- 客户端或本机手动写入输出点位，立即取消相关序列并保留手动值。要重新触发，先在基础点位区选择该输出并点击「恢复自动模拟」，再让源条件重新进入。

## 暂停、重置和从站启停

暂停冻结剩余延时和条件监听，继续后重新建立条件基线，不积压暂停期间的触发。重置取消全部序列、释放控制权并恢复扩展输出初始值；原基础规则点位也按既有语义重置。

停用某从站会取消它的延时动作及保持输出，保留当前运行值，其他站继续运行。再次启用后，条件规则等待新边沿，无条件规则在场景运行时重新执行，不补执行旧动作。离线时重置的扩展输出在该站下次启用时先恢复初始值。停止服务、重开项目均不恢复之前的执行实例。

场景是桌面联调用途，不承诺硬实时。日志记录计划时间及实际时间；到期动作延迟超过 1000 ms 时取消该次序列，避免长时间卡顿后集中补写。

## 保存、复制与日志

仅含原有固定值条件联动的 Modbus TCP 方案使用 v5，项目使用 v9；使用点位取值或无条件规则时，方案使用 v6、项目使用 v10，独立扩展包使用 v2。不含这些功能时沿用原版本。旧方案和项目可继续读取，旧程序会拒绝新版本，防止将点位取值误作固定值执行。

复制从站、导入扩展包及改变 Unit ID 后，扩展设为停用，需要重新检查并应用。引用使用相对从站地址，复制后不会写源站。删除被引用点位、改变地址、类型或字序会被拒绝；请先编辑或移除相关扩展。

「导出扩展…」保存独立 JSON 包，「导入扩展…」绑定当前站并校验依赖；不执行导入源码。普通点位 JSON/CSV 仍只包含点位和基础规则。完整项目保存扩展源码与计划，但不保存当前值、延时队列或本机许可。

请求日志中的「场景引擎」记录触发、执行步骤、完成、取消和释放，独立于网络请求，不生成虚假 RX/TX，也不计入请求成功率。清空日志不会停止序列，后续步骤继续记录，报告沿用日志记录起点与缺失标记。

首版限制：每站 100 条规则、每规则 1000 个动作时刻、每服务 256 个同时执行实例；源码最大 256 KiB，单份扩展定义最大 1 MiB。超过限制将拒绝检查或触发。
