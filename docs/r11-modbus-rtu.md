# R11 · Modbus RTU 交付记录

2026-11-14。分支 `codex/r11-modbus-rtu`。状态：软件预览版，实机串口验收待完成。

## 已实现

- Windows COM 枚举与手动输入；默认 9600 / 8E1，可调波特率、校验、停止位和超时。串口名称归一化，客户端和服务端共用进程内端口占用检查，打开失败、取消和关闭时释放。
- 客户端支持单播站号 1–247，读取 HR、IR、Coil、DI，写入 HR、Coil。沿用 Modbus 数值编解码、字序、队列、点表、工程值及写入回读。
- 不自动重试。超时、取消或无效应答后暂停对应站号，其他站号继续。用户检查链路并确认旧应答结束后重新连接。已发送但没有有效回执的写入保留未知结果。
- 串口模拟端支持多个站号、点位、当前值、场景和故障注入。错误 CRC 不执行写入，广播和未配置站号保持静默。
- 点表 JSON 保留协议键，CSV 使用 Modbus 字段并按 RTU 校验；SQLite 方案、日志、写入证据往返及报告串口参数摘要可用。
- 项目 v4 增加 RTU 方案，旧 v1–v3 和旧 SQLite 项目补默认停止方案。新版项目 SQLite 的 user_version 为 2，旧版应用会拒绝打开；本地库结构仍为 v1。
- RTU 诊断展示站号、功能码、数据及 CRC，残缺和校验失败显示解析错误。

使用锁文件中的 PyModbus 3.16.2 和 pyserial 3.5。TCP 与 RTU 共用读写及响应校验，TCP 保留 MBAP 验证。StrictRtuFramer 修正当前库在跳过外站应答时消耗整段缓冲区的问题，保留同一 USB 读取中的后续帧；仍复用库的帧长度判断、CRC 和 PDU 解码。升级依赖后需重新验证异常及迟到帧。参考 [PyModbus 官方客户端文档](https://pymodbus.readthedocs.io/en/latest/source/client.html)。

- 新增 20 项 RTU 测试，使用真实 PyModbus 编解码与内存串口替身，覆盖双站读写、超时隔离、CRC、截断、错误站号／功能码／长度／写回显、迟到帧、广播静默、端口冲突、打开失败／取消、重复关闭、未知写入、自动回读、场景方案、报告摘要、项目迁移、JSON/CSV 和桌面配置往返。

- 最终可执行文件使用隔离数据目录和 offscreen Qt 启动，运行 6 秒未提前退出，未发现 Python 导入错误，随后结束测试进程。这只验证基础启动，不代表打包版串口互通已验收。
- 原工作区已有点位排序改动保留，并纳入回归。
