# Modbus TCP 服务端设计

开发前设计稿 · [角色选择与服务端界面草图](modbus-tcp-server-draft.html)

## 1. 目标与首版范围

工业协议调试台新增服务端模式。用户可在一个 TCP 监听端点下配置多个虚拟从站，用现有客户端、PLC、HMI 或上位机访问各站的点位。典型用法是模拟仪表读数和开关输入，检查客户端的地址映射，以及验证远程写入是否落到正确的站和数据区。

首版交付角色选择页、单个 Modbus TCP 监听器、多从站点位配置、实时值查看与修改、一个本地方案，以及请求日志和 RX/TX 报文。多寄存器类型、脚本、自动变化曲线和多个监听器留给后续版本。

## 2. 启动与角色切换

每次打开应用进入角色选择页。两张卡片用方向示意区分请求的发起方，分别提供「进入客户端」和「进入服务端」。协议选择放在工作台内，首版固定为 Modbus TCP。

进入服务端时恢复上次保存的方案，监听状态为「已停止」。返回首页或关闭窗口时，正在运行的服务先提示用户确认停止。若有未保存的方案编辑，提供「保存并离开」「放弃修改」「取消」。只有保存或放弃完成、运行中的会话完成清理后才离开页面。每个实例一次进入一个工作台，本机联调可打开两个实例。

## 3. 界面草图与交互

浏览器草图展示三部分：[角色选择](modbus-tcp-server-draft.html#role)、[服务端工作台](modbus-tcp-server-draft.html#workbench)和[新增点位表单](modbus-tcp-server-draft.html#point)。草图中的站点、日志和报文为示例数据。

| 区域 | 内容与操作 |
|---|---|
| 标题栏 | 返回首页、当前协议、监听状态。状态使用文字和颜色区分。 |
| 监听设置 | 地址、端口、「启动服务」或「停止服务」。失败原因显示在设置旁。 |
| 从站列表 | 新增、选择、编辑和删除从站。列表显示 Unit ID 和名称。删除前确认该站及其点位数量。 |
| 点位表 | 按 HR、IR、Coil、DI 切换数据区。支持添加、批量添加、编辑和删除。列为偏移、名称、类型、初始值、当前值。 |
| 方案 | 「保存方案」持久化结构和初始值，显示「有未保存修改」或「已保存」。 |
| 请求日志 | 时间、来源客户端、Unit ID、功能码、起始偏移、数量和结果。选中日志查看原始 RX 请求和 TX 响应。 |

视觉沿用现有 Qt 工作台。深蓝 `#142A40` 用于标题栏，浅灰蓝 `#EDF2F6` 用于背景，白色 `#FFFFFF` 用于工作面，青色 `#0F6570` 用于主操作，绿色 `#154C47` 用于监听状态。中文使用微软雅黑，地址和值用等宽字体，数值右对齐。服务端日志和报文区之间可拖动，给点位表和报文留出可调空间。

**新增点位**在当前从站和数据区下打开。用户填写 0 基偏移、名称（可选）和初始值。数据类型由数据区确定，表单显示类型和有效范围。批量添加使用起始偏移、数量和统一初始值，预览占用的闭区间。整批校验成功后才创建，遇到重复地址或越界时标出第一处冲突。

**运行中**可编辑当前值。远程写入成功后，同步更新点位表并记录请求。当前值显示最新已提交值，同一地址由本机修改和远程写入时，按后台处理顺序生效。停止后清空运行态显示，以 `—` 表示。监听参数、站号、数据区、偏移和初始值的编辑入口在运行中禁用。

## 4. 从站与地址模型

配置层级为「监听端点 → 从站 → 数据区 → 点位」。同一个 Unit ID 下，四个数据区各有自己的地址空间。不同从站之间的点位和值相互独立。

| 数据区 | 首版类型 | 客户端访问 | 首版功能码（十进制） |
|---|---|---|---|
| HR 保持寄存器 | UInt16，0–65535 | 读写 | 03 读，06 写单个，16 写多个 |
| IR 输入寄存器 | UInt16，0–65535 | 只读 | 04 读 |
| Coil 线圈 | Bool，开或关 | 读写 | 01 读，05 写单个，15 写多个 |
| DI 离散输入 | Bool，开或关 | 只读 | 02 读 |

IR 和 DI 的只读权限适用于远程请求。本机可配置初始值，也可在运行中修改当前值以模拟输入。保留原始位和寄存器作为协议存储单位，后续扩展 Int16、UInt32 或 Float32 时，再为显示和输入增加编码、跨度与字序配置。 [Modbus 应用协议规范，第 4、6 节](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)

- **从站号**沿用现有客户端的 `1–255` 工具范围，同一方案内唯一。按请求里的 Unit ID 精确匹配，关闭广播和默认站回退。未知 Unit ID 采用锁定版本 PyModbus 的缺站异常 `0x0B`，并写入日志。
- **偏移**使用 `0–65535`。点位键为 `(Unit ID, 数据区, 偏移)`。配置阶段拒绝同区重复和越界。界面明确标注「0 基偏移」，例如 `HR / 0` 对应常见参考编号 `40001`。
- **请求范围**必须完整落在已配置地址内。命中空洞或越界返回 `0x02`。多点写入先校验整段再更新，任意地址失败时整段保持原值。首版功能码白名单以表格为准，未启用的功能返回 `0x01`。
- **配置与运行分离**。例如站 1 的 `HR / 0` 初始值为 `1200`，站 2 的同址值为 `900`。远程把站 1 写成 `1300` 后，站 2 仍读出 `900`，下次启动从方案的 `1200` 重新初始化站 1。

## 5. 监听生命周期

默认地址 `127.0.0.1`、端口 `1502`。局域网联调时选择本机网卡 IP。端口范围为 `1–65535`，可按设备要求改用 `502`。启动前校验至少配置一个从站和一个点位。启动采用当前编辑中的有效配置，用户可用「保存方案」将该配置留给下一次打开。

| 状态 | 行为 |
|---|---|
| 已停止 | 可编辑方案、启动监听。端口占用或地址无法绑定时回到此状态，保留编辑内容。 |
| 启动中 | 创建当前值表并绑定监听端口。阻止重复启动，绑定成功后才显示「监听中」。 |
| 监听中 | 响应请求，允许查看报文与修改当前值。远程写入与本机改值在同一个 I/O 循环串行提交。 |
| 停止中 | 关闭监听及已接受的连接，结束会话任务。释放端口后回到「已停止」。 |

## 6. 结构与扩展

继续使用 Python 3.12、PySide6 Widgets 和现有异步 I/O 桥接。服务端会话与客户端会话分开，角色入口负责构造对应的工作台。可共享 Qt 组件和日志存储机制，协议点位结构由各自的适配层定义。

| 层 | 设计职责 |
|---|---|
| 启动入口与 UI | 角色选择和工作台导航。使用 Qt 表格模型呈现点位与日志，通过信号接收状态和点位更新。 |
| 服务端应用层 | 管理 `start`、`stop`、本地改值和运行状态。将运行事件转为界面与日志所需的数据。 |
| Modbus TCP 适配层 | 复用 `Area` 和功能码规则，校验 Unit ID、地址、值及请求范围。用 PyModbus 的实例级服务端和数据模型实现监听与请求处理。 |
| 本地存储 | 保存带 `schema_version` 的 Modbus TCP 方案和独立的服务端请求日志。 |

运行时点位表只有一个写入源，由 I/O 线程持有。Qt 线程通过命令修改当前值，通过事件刷新表格。PyModbus 类型和地址映射留在适配层。实现时用锁定版本做契约测试，确认空洞、缺站、功能码限制、远程写入事件和本地改值使用同一份运行数据。 [PyModbus 数据模型与迁移说明](https://pymodbus.readthedocs.io/en/v3.16.0/source/upgrade_40.html)

## 7. 本地保存

沿用 `%LOCALAPPDATA%\AllProtocol`。拟用 `modbus-tcp-server.json` 原子保存最近一套方案，包含版本、协议、监听地址、端口、从站和各点位的名称、偏移及初始值。方案读取失败时提示文件路径并进入可编辑空方案，只有显式保存后才替换文件。

拟用 `server-requests.jsonl` 记录请求摘要和原始报文字节。追加后将超过 `5,242,880` 字节时清除旧记录，从本条开始。界面展示最近 500 条。监听启动、停止和失败也可用事件行显示，报文区在无数据时显示 `—`。

## 8. 开发顺序与验收

1. 完成角色入口和服务端配置模型，验证每次打开都能选角色、客户端可正常使用、重复地址和批量越界会被拦截。
2. 完成监听和四区读写，使用实际 TCP 客户端验证两站同址读出不同值、四区功能码映射、边界偏移 `0` 和 `65535`、跨空洞异常以及多点写入失败时无部分更新。
3. 接入服务端工作台和存储，验证远程写入只更新目标从站、本机改 IR 和 DI 后客户端能读到新值、重启后恢复初始值、日志到达上限后的清理与展示。
4. 验证端口占用提示、停止后可重新绑定、退出时连接清理，以及 Windows 打包产物可用两个实例完成本机联调。
