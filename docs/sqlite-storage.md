# SQLite 存储

本地数据使用 `%LOCALAPPDATA%\AllProtocol\allprotocol.sqlite3`；项目使用独立的 `.allprotocol` 文件。依赖 Python 标准库 `sqlite3`，不需要安装数据库服务。

## 数据模型

| 表 | 数据与约束 |
| --- | --- |
| `metadata` | 文件用途、本地迁移完成标记、项目名称及可选工作区布局 |
| `connections` | 本地连接配置，协议与端点唯一，按最近使用排序 |
| `devices` | 项目设备、稳定 ID、名称、连接参数和显示顺序 |
| `point_tables` | 点表配置及所属设备，设备删除时级联删除 |
| `named_points` | 点位定义及所属点表，点表删除时级联删除 |
| `server_plans` | 按协议保存的监听参数与方案编码版本 |
| `server_stations` | Modbus 从站及顺序 |
| `server_points` | 服务端点位及顺序，方案删除时级联删除 |
| `simulation_rules` | 每个服务端点位的一条模拟规则，随点位级联删除 |
| `journal_state` | 各日志来源的轮换时间和旧日志损坏标记 |
| `journal_entries` | 请求或生命周期事件，按来源和递增 ID 建索引 |

协议特有的连接字段、点位定义、模拟参数及日志证据使用 JSON 文本列；实体关系、排序、唯一约束和日志索引由 SQLite 管理。这样可复用现有协议校验，并保留 UInt64 等超出 SQLite 有符号整数范围的数值精度。场景时钟、当前采样值和手动接管状态不持久化。

SQLite `application_id` 为 `0x41505254`，`user_version` 为 1。项目内部配置编码沿用原有项目 v3 及各协议方案版本，它们与数据库结构版本独立。数据库用途分为 `local` 和 `project`，不接受未知版本或其他应用的数据库。

## 事务与保存

本地操作使用独立连接和 `BEGIN IMMEDIATE` 事务，启用外键，锁等待最多 5 秒；异常时关闭连接回滚。连接历史更新、方案点位及规则替换、日志轮换与追加各自整体提交，避免并发写入丢失更新。

项目在内存 SQLite 中构建完整快照，校验后通过 `QSaveFile` 原子替换目标。打开时校验数据库完整性及外键，保存时继续检查文件修订，拒绝覆盖外部修改或已删除的文件。项目不包含本地连接历史和运行日志。复制项目只需要复制单个文件，文件大小限制仍为 10 MiB。

日志分为客户端、Modbus 服务端、S7 服务端三个来源，按写入顺序展示各自最近 500 条。每个来源以 UTF-8 日志内容字节数计算 5 MiB 轮换阈值；清除与新记录写入在同一事务中执行，保留轮换时间。数据库文件还包含表、索引及可复用页面，物理大小不等于日志内容大小。

## 旧数据迁移

旧 `connections.json`、两种协议的方案 JSON，以及三个请求 JSONL 在首次访问对应来源时迁移。迁移数据和完成标记在同一事务提交，失败可修复原文件后重试；成功后不再重复导入。原文件不修改、不删除。无效连接或方案会报错；日志中的坏行被跳过并标记不完整，超过原有 5 MiB 上限的旧日志按原轮换规则处理，同时保留原件。

旧 JSON v1/v2/v3 项目可直接打开，打开时不修改源文件；保存时写成 SQLite。使用「另存为…」可保留旧 JSON 项目。点表 JSON/CSV 导入导出和报告 ZIP 中的 JSON/CSV 格式保持原有契约。

备份本地数据时，退出程序后复制 `allprotocol.sqlite3` 即可。旧 JSON/JSONL 仅作为迁移原件保留，后续修改这些文件不会影响已经迁移的数据库。
