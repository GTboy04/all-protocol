## 交付范围

- Modbus 场景窗口通过公开分组接口选择 Unit ID，点位以完整目标标识绑定，选择同步到主界面。筛选同时覆盖基础规则与扩展；全局启动/暂停/重置仍控制整个模拟服务。
- Modbus TCP 条件联动表单支持六种比较与无条件执行、浮点容差、首次满足触发、条件失效取消、同一时刻多目标赋值，以及完成后保持或释放输出。
- 动作支持手动固定值或选择同一从站点位，在执行时复制其当前值；同一步先读取全部来源，再写入目标。SDK 支持点位引用值与 `scene.always(...)`。无条件规则启动场景时执行一次，暂停继续不重复。
- Python SDK v1 支持 `Scene`、`Step`、`build(scene)`，检查在有超时和取消的进程中完成。主进程再次验证计划，Qt 检查异步进行。Windows 打包进程使用自身 `--scene-worker` 入口，无需系统 Python。
- 按真实写入提交捕获边沿，支持多寄存器点位的部分写入；源点在两个 tick 之间恢复，也不会丢失已提交的触发。内部扩展赋值不递归触发。
- 场景时钟与动作堆支持延时、暂停继续、取消及延迟过大保护；忙时忽略重触发。取消时移除旧动作，避免高频取消导致堆积。
- 输出所有权覆盖扩展全部目标；基础规则暂让输出，完成默认保持最终值。显式释放时使基础规则缓存失效，按当前场景时间恢复。手动/客户端写入取消相关序列并保持接管优先级。
- 仅有扩展、没有基础规则时也可运行场景。停止从站立即取消该站动作，重启不补写旧任务；离线重置在下次启用站点时恢复输出初始值。
- 定义贯穿本地 SQLite、项目 JSON/SQLite、旧式服务和多模拟设备路径。固定值扩展方案使用 v5、项目使用 v9；含点位取值或无条件规则时使用方案 v6、项目 v10 和扩展包 v2，防止旧程序忽略新语义。无扩展沿用原版本，仍兼容旧数据。
- 复制/导入扩展及修改 Unit ID 后停用并清除检查摘要，须重新检查。删除引用目标或改变类型、字序会阻止应用，避免失效引用继续运行。普通点位 JSON/CSV 不夹带扩展源码。
- 类型化场景日志独立于请求，记录来源提交、前后值、执行/步骤、计划/实际时间、会话和从站代次。后台日志队列、诊断和报告均支持，清空日志不取消执行。

## 同批运行控制

- Modbus TCP 从站独立启停保留当前值；停止全部从站仍保留监听。服务端「重置点位」恢复全部配置初始值并重置场景，监听与客户端连接保持；停止从站的值在下次启动时恢复。该按钮也支持 S7、RTU 和 OPC UA。
- 客户端、服务端日志支持暂停输出，通信与日志存储继续，恢复后显示最新保留记录；清空日志通过后台写入队列屏障执行。
- Bit 查看格子只显示位编号与当前值，名称、掩码和业务含义在点击后显示。

## 边界

首版针对同一 Modbus TCP 服务、同一从站内的联动。RTU 明确拒绝扩展定义；S7、OPC UA 沿用基础场景。

Python 是检查期的计划生成接口，不提供任意运行期回调。独立进程不是安全沙箱，本机许可不随项目传播。暂停时不积压边沿，重开项目不恢复运行任务，运行中不能修改定义。

资源上限为每站 100 条规则、每规则 1000 个动作时刻、每服务 256 个同时执行实例；测试覆盖第 257 个及以后执行被拒绝，以及取消后清理资源。延迟超过 1000 ms 取消序列；不承诺硬实时或所有中间值都能被外部轮询观察。现场长时间稳定性和具体硬件负载仍需按使用环境验收。
