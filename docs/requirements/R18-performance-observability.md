# R18 · 调度可观测性与性能优化

2026-11-15 · 状态：计划中，尚未实施。

## 目标与依赖

依赖 R3、R4、R8。说明采样实际花费在哪里，并为多设备、大点表及录制建立可重复的性能基线。本计划可独立推进，基线测量建议在 R14 开始前完成。

## 首版范围

- 分别展示期望轮询周期、实际轮次完成间隔、轮次执行耗时、排队时间、请求响应时间和跳过周期数。
- 展示每设备、每组的请求数、读合并前后数量、超时率及手动任务等待情况。
- RTU 在总线指标之外显示站号耗时和失败分布；OPC UA 订阅显示请求/修订间隔、通知频率和溢出，不套用轮询往返耗时。
- 生成可导出的性能摘要，明确采集时段、指标定义、统计样本数和日志缺失边界。

## 实施步骤

1. 先定义指标时间边界，以单调时钟在入队、调度、发送和完成位置埋点；不把排队时间误记为设备响应时间。
2. 建立固定场景：单设备大点表、多设备并行、同设备多组轮询、慢站号与正常站号共存，以及手动请求插入。
3. 按设备数、点数、周期、合并率和错误比例逐级增加负载，记录 CPU、内存、句柄、界面交互耗时及采样延迟。TCP/S7、RTU、OPC UA 分别记录。
4. 根据测量定位表格刷新、跨线程事件、日志持久化或协议等待瓶颈，再选择增量刷新、刷新合并、模型视图或后台批处理。
5. 有新增录制或取证功能时复跑相同负载，对比功能开启前后成本；不为每次文案变动重复性能测试。

## 边界

- 已有公平排队、读取合并及错过周期跳过机制继续保留，不把这些能力重复列为新增功能。
- 不通过无限队列或无限缓存掩盖过载；容量达到上限时保持可见的拒绝、降频或缺失提示。
- 首版不自动改变用户采样周期，不跨不兼容地址范围强行合并，也不增加未知写入的重试。
- 在协议和设备限制未验证前，不承诺统一的最大点数或刷新频率。

## 验收

- 使用可控时钟验证排队、执行及跳过周期指标；模拟慢响应时能区分队列拥堵与设备响应慢。
- 每份性能报告包含环境、版本、负载、测量方法和原始结果，可按同一配置复现。
- 明确至少一组“推荐负载”和一组“过载负载”，在实现前根据基线确定交互耗时、内存及采样延迟的数值目标，禁止只以“流畅”验收。
- 优化后用同一负载对比，不破坏手动请求公平性、设备故障隔离和有界内存；过载时仍能取消、断开和关闭项目。

## 交付物

指标定义、运行诊断视图、可复现基准场景及结果、针对实测瓶颈的优化和回归记录。
