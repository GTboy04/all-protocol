# R17 · 条件触发与异常取证

2026-11-15 · 状态：计划中，尚未实施。

## 目标与依赖

依赖 R3、R8、R10、R14。利用趋势历史和请求证据捕获偶发问题，形成“异常发生前后发生了什么”的完整记录。

## 首版范围

- 支持越上/下限、变化速率、持续不变、连续超时和质量变化等单点条件。
- 配置持续时间、恢复回差、冷却时间和重复触发策略，显示待满足、已触发、已恢复及被抑制状态。
- 配置触发前、后保留窗口。例如压力越限持续 3 秒，保存前 30 秒和后 60 秒。
- 取证包包含规则与目标快照、样本质量、相关连接/写入/故障事件及窗口内已捕获的日志，支持离线查看和报告导出。

## 数据与实现

1. 实现独立于 Qt、可注入时钟的条件状态机；持续时间使用单调时钟，记录同时保留可读时间及明确时区。
2. 越限和速率只消费有效采样，质量异常不以旧值继续累计。速率按真实采样间隔计算，重连和长缺口后重新建立基线。
3. “持续不变”必须持续收到有效观察，不能把订阅长期无值通知当作设备卡死；需要时显式启用确认读取并纳入调度负载。
4. 复用 R14 的有界环形缓存和录制格式，在触发时固定前窗并继续收集后窗。重叠窗口允许共享数据，但各触发事件保留独立身份。
5. 记录取证期间应用退出、磁盘失败、缓存不足和日志已轮换等缺口，不承诺恢复此前未采集的报文。

## 边界

- 首版仅提供应用内事件和取证导出，不发送短信、邮件或远程告警。
- 规则不自动写入设备，不执行任意脚本，不作为控制或保护逻辑。
- 规则定义随项目保存，计时器、触发状态和采样缓冲不随项目恢复。修改规则后开始新的规则版本。
- 跨设备复合条件、逻辑表达式和自动控制动作留作后续独立评估。

## 验收

- 边界抖动、延时触发、回差恢复和冷却策略确定且可复现；断线、旧代次和 Bad/Uncertain 不导致错误的数值触发。
- 通过模拟场景与故障注入复现每类条件，验证前后窗口、事件时间与报告一致。
- 连续超时按目标的实际请求结果计数，明确何时清零；“无请求”和“请求超时”分开处理。
- 录制不足一个前窗、连续触发、关闭项目和存储失败时，能导出已捕获内容并注明完整性。

## 交付物

规则配置、事件列表、窗口取证与离线导出、条件状态机测试，以及示例异常场景。
