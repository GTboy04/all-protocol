# R13 · 现场验收与运行恢复

2026-11-15 · 状态：软件功能已实现，现场及 24 小时稳定性验收待完成。实现与回归见[阶段交付记录](../r13-runtime-reliability.md)。同阶段交付用户追加的 [R20 点位功能描述与搜索定位](R20-point-definitions.md)。

## 目标与依赖

依赖 R3、R4、R11、R12 的软件基线。补齐 RTU 和 OPC UA 的现场验收，并让长时间运行、意外断线及恢复过程可观察、可控制。软件功能验收和硬件互通验收分别记录，不以自动化通过替代实机结论。

## 首版范围

- 为每个设备提供自动重连开关、重试间隔与上限；默认关闭，主动断开、取消连接和关闭项目时停止重试。
- 明确展示连接中、已连接、等待重试、恢复失败，以及最后成功通信时间、尝试次数和下次重试时间。RTU 的端口已打开与各站号可达性分开显示。
- 单独配置是否恢复意外断线前的轮询或订阅。恢复使用新会话身份和代次；用户停止、修改或删除的任务不得复活。
- OPC UA 分开显示订阅保活状态、最后值通知时间、数值最后变化时间和原生数据质量。无新通知本身不能判定连接失效，也不能把旧值重新标为刚采样成功。
- 完成 Windows 打包版的串口链路、拔插、多站轮询和独立厂商 OPC UA 服务端互通记录。

## 实施步骤

1. 在会话层建立恢复状态机，统一主动停止、意外断开、重试等待和取消；重连失败采用有上限的退避策略。
2. 保存允许恢复的读取任务配置，复用现有会话代次、运行身份和旧事件隔离机制。RTU 对迟到帧的站号隔离限制继续保留，不能靠自动重连直接绕过。
3. 接入工作区状态展示及设备级配置；配置保存与迁移遵循现有项目版本规则，运行中的重试计数不写入项目。
4. 先完成可控断线测试，再执行打包版现场验收与长时间运行检查。

## 边界

- 不自动重发写入，不恢复未完成的写入队列；已发出的未知写入继续显示结果未知。
- 证书变化、身份不符或权限失败不能自动降级为匿名或无加密连接，须明确提示配置问题。
- RTU 设备拔插后若端口名称变化，不自动猜测替代端口。各设备恢复互不阻塞。
- 不承诺跨程序重启恢复运行任务，也不在本计划加入后台服务。

## 验收

- 断网、设备重启、串口拔插、端口占用、重连失败和重试期间关闭项目均能正确结束并释放资源。
- 恢复后原读取任务按用户选择运行，旧会话通知和旧采样不更新新会话；未知写入发送次数不增加。
- OPC UA 变量持续不变但订阅保活正常时，不显示为会话断开；服务端失联、Bad/Uncertain、通知溢出分别可识别。
- 建议以连续 24 小时作为首轮稳定性验收窗口，记录设备数、点数、采样周期、内存和句柄变化，以及中断、恢复和丢失记录。
- 现场证据注明硬件、驱动、固件、串口参数、服务端厂商及应用构建版本。尚无硬件的项目保留待验收状态。
