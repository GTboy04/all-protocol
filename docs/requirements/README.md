### 建议实施顺序

1. 优先推进 R13；在 R14 开始前完成 R18 的指标定义与性能基线。缺少现场硬件的验收项单独保留待验收，不阻止可独立验证的其他功能开发。
2. R14 先交付实时趋势、会话录制和离线查看，再扩展报告曲线。R16 可作为独立增量插入。
3. 推进 R15，复用现有调度、模拟、故障和写入证据；R14 曲线是附加证据，不作为执行器的硬依赖。
4. 在 R14 之后开发 R17。R18 的性能优化随实测瓶颈推进；R19 在用户场景、设备与验收条件明确后逐项立项。

各计划文档分别定义首版范围、实现边界、验收与交付物。共享约定：保留旧项目兼容，运行状态不混入配置；未知写入不自动重放；历史采样与有界请求日志分别存储；未完成实机验收的协议保留相应标签。
