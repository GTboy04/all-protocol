# R8 请求诊断与故障注入

## 目标与依赖

依赖 R3、R5、R7。将原始报文与请求结果关联起来，并可主动复现联调故障。

## 诊断功能

按设备、时间、操作和错误筛选日志；选中请求显示协议字段树、原始十六进制及字节高亮。展示窗口内请求数量、失败比例、平均/分位耗时；明确统计窗口和剔除项。

## 故障功能

模拟服务支持匹配规则：下一次/指定次数/持续时间的响应延迟、异常响应、主动断开。首版只提供明确模板，不做任意畸形字节编辑。故障状态在服务视图持续可见，停止或重置清除运行计数。

## 实现与边界

协议解码器只解释捕获数据，解析失败保留原始帧并定位失败位置。请求与报文使用 R4 唯一会话 ID + 请求 ID 关联；被动日志查看不触发网络请求。故障执行在 R5 适配器边界，延迟任务可取消。

## 验收

标准帧字段偏移正确；残缺帧不使界面崩溃；筛选与统计口径一致；一次性故障只影响一次；停止延迟服务释放连接；大量日志不阻塞采样。未知写入结果不能被显示成已拒绝。

## 交付记录

2026-11-10 · 已完成。分支 `codex/r8-diagnostics` 基于包含 R7 的 `main` 提交 `2ba9ced`。

- 项目工作区与本地客户端、服务端均可从请求日志打开「请求诊断」。按设备或来源客户端、最近 1／5／15／60 分钟、操作和错误筛选。选中请求后按会话与请求编号定位捕获报文，点击协议字段高亮原始字节。Modbus TCP 展开 MBAP 与常用读写 PDU，S7 展开 TPKT、COTP、协商、读写与错误字段，支持 COTP 分段重组。残缺帧保留原始字节，并标出首个解析失败的偏移。较早的日志仍可查看。
- 筛选和统计使用同一份最近 500 条日志。统计包含筛选后的读写，剔除输入错误和排队取消的未发送项。没有耗时的旧记录参与请求数与失败率，延迟分位采用最近秩。客户端耗时包含设备应答等待，服务端耗时从接收完整请求算到提交应答或中止。未知写入单独计数。
- 每个监听可设置一条运行时故障规则，匹配读、写或两者，作用于下一次、指定次数或指定时段内的匹配请求。延迟模板先执行请求再等待应答，异常模板直接返回 Modbus `0x03` 或 S7 `0x8104`，主动断开模板关闭该客户端连接。监听页持续显示规则及触发数。重置或更换规则会解除已在等待的延迟，停止监听会取消延迟并关闭连接。
- 全量 216 项测试通过。新增 12 项覆盖双协议真实连接上的故障注入与写入结果、监听清理、并发 Modbus 请求、字段偏移、截断帧、筛选统计、日志兼容及界面高亮。项目界面测试在诊断窗口加载 500 条日志时验证采样继续更新。
