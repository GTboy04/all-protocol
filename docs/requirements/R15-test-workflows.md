# R15 · 可重复执行的联调用例

2026-11-15 · 状态：计划中，尚未实施。

## 目标与依赖

依赖 R3、R4、R7、R8、R9、R10，建议在 R13 后实施。将现有读写、场景、故障和验证能力组合为可保存、重复执行、交付结果的联调流程。R14 的曲线可作为后续附加证据，不是首版执行器的硬依赖。

## 首版范围

- 提供可视化有序步骤：读取、写入、固定等待、断言、等待条件、启停模拟场景和启停故障。
- 断言支持相等、数值范围、绝对/相对容差；等待条件必须配置超时。首版不提供任意 Python、表达式脚本、循环或并行分支。
- 步骤通过稳定 ID 引用项目设备和点位，编辑时预览实际目标；运行前检查目标、类型、权限和配置是否仍有效。
- 每步配置失败后停止或继续；结果区分通过、失败、超时、取消、跳过和无法判断，并保留实际值与质量。
- 用例定义随项目保存，运行结果单独归档；报告关联步骤、请求、写入回读和故障事件。

## 运行与证据

1. 先实现独立于 Qt 的步骤模型、校验器和顺序执行器，再接入编辑及运行界面。
2. 执行沿用设备调度队列，不直接绕过会话访问协议适配器。界面显示执行进度及手动操作与后台轮询的并发情况；不声称步骤间具备事务隔离。
3. 运行前冻结用例与所引用的目标配置，运行中修改目标须使相关步骤失效或中止，不能静默改用新地址。
4. 每步记录开始/结束时间、期望、实际、质量、请求身份和失败原因。条件步骤使用运行后产生的有效数据，旧值及 Bad/Uncertain 不能判为通过。
5. 导出复用 R10 的快照和原子保存机制；后续可关联 R14 的指定录制区间。

## 写入与清理边界

- 执行前展示所有写入目标及值，由用户启动本次运行；不允许通过用例引入无提示的后台写入。
- 写入结果未知时停止后续依赖步骤，不能自动重试或当作明确失败。允许用户独立读取核对。
- 停止后不再调度新步骤；在途写入可能已经生效，不承诺回滚设备状态。
- 默认清理本次运行新启动的模拟场景和故障，保留运行前已有状态；清理失败也要进入结果记录。

## 验收

- 用本机模拟端运行“写入 → 回读 → 等待范围 → 注入延迟 → 验证超时 → 清理”完整流程，多次执行证据可区分。
- 覆盖步骤失败、旧值、质量异常、设备断开、未知写入、目标被删除、运行取消和项目关闭。
- 用例保存与重新打开无语义变化；报告步骤计数、结论和实际请求证据一致，清理失败不能隐藏。

## 后续扩展

首版稳定后再增加命令行执行、明确的退出码和回归结果对比。默认使用模拟端的自动回归入口，真实设备执行仍须显式选择配置；任意脚本保持独立需求。
