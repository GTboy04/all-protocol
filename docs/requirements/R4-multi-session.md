# R4 多设备独立会话

## 目标与依赖

依赖 R3。项目中多台 Modbus TCP / S7 设备可同时连接和轮询。

## 行为

- SessionManager 以稳定 device_id 管理 Session、调度器和连接状态。
- 每台设备独立连接、断开、开始或停止轮询；切换视图不停止后台设备。
- 全部断开执行可追踪的批量清理，不遗留 socket 或任务。
- 连接中修改端点须先断开；删除活动设备需先完成停止。
- 首版保持手动重连，不自动重放任何写请求。

## 实现

所有运行事件携带 device_id 和会话 generation，日志增加唯一会话 ID。Qt 桥接保持一个受管 I/O 运行时，多个设备在其中运行；不按点位新建线程。UI 的选中设备状态与连接真实状态分离。

## 失败与限制

设备故障只影响本设备；批量连接显示每台结果，不能用一个总布尔值掩盖部分失败。禁止已删除或旧 generation 的事件复活界面数据。窗口关闭等待管理器资源收束。

## 验收

两个协议至少各一台同时连接；其中一台超时另一台继续采样；切换设备保留结果；删除与退出期间无后台任务泄漏。用本地模拟服务测试跨设备隔离及端口释放。

## 实施设计（2026-11-07）

分支 `codex/r4-multi-session`，从 R3 `df739b0` 创建。保留 R1–R3 分支，不改写、合并或推送。

### 会话与线程

项目客户端使用一个 IoBridge 和 SessionManager，所有设备 Session 在同一个 asyncio I/O 线程内运行。MainWindow 仅持有设备绑定的命令句柄，提交协程时捕获 device_id；后台执行不依赖随后变化的界面选中项。本地调试模式继续使用原来的单设备 Session。

每台设备独立保留 Session、调度器、状态、采样及快速读取结果。每次连接生成唯一 session_id，设备运行实例另有 runtime_id，代次 generation 在每个 Session 内递增。所有运行事件使用 DeviceEvent 信封携带这些身份；日志及 ReadUpdate.entry 也包含 device_id、session_id 和 generation。旧日志缺少新增字段仍可读取，项目格式继续为 v3。

DeviceEvent 同时携带不可变连接配置快照，界面据此保护运行配置；即使新草稿匹配同一端点，也不能通过保存表单覆盖另一台正在运行的设备参数。

Session 的握手使用自身拥有的任务，断开仅取消握手任务，不等待调用者整段协程，避免批量连接与全部断开相互等待。

### 界面与配置

沿用现有客户端窗口，项目设备选择器在连接期间也可切换，并显示每台设备状态。新增「新增设备」「连接全部」「断开全部」和连接概览。切换仅恢复该设备的表单、结果、日志和采样，不停止后台任务；R6 再做设备树与统一工作区。

保留 R1 的配置约定：相同协议/端点更新配置，不同端点保存为另一台设备。正在连接或已连接的设备不能编辑连接参数；新增设备进入离线草稿，原设备继续运行。每台设备的点表仍以稳定 ID 关联。打开项目不自动连接。

批量连接先校验已保存配置，各设备独立连接并返回逐台结果；一台失败不取消其他设备。界面显示成功/失败数及详情，选择器显示每台实际状态。全部断开期间拒绝新连接及请求，完成后可手动重连。

### 事件、采样和日志隔离

界面为每台设备保存独立 SampleStore，绑定时仅注册其点表。后台采样更新相应存储；切回后显示最新值。不同设备即使 generation/request_id/地址相同也不能相互覆盖。移除的运行实例令牌进入退休集合，旧事件不能恢复设备或修改新实例。

所有设备的日志统一追加本机 requests.jsonl，选中设备时按 device_id 展示；旧日志按协议/端点兼容匹配。草稿未选设备时展示本机最近记录。日志详情显示设备、唯一会话 ID、代次、任务和请求 ID，避免多会话编号冲突。

### 移除与退出

删除确认说明点表影响和先停止设备。确认后先异步断开、清空该设备任务并等待资源收束，再移除配置、点表、采样及缓存；不会停止其他设备。清理期间暂不允许保存项目快照，避免写入一份尚未完成删除的配置。

关闭客户端先保存有效表单到项目内存，再由 Manager.shutdown 阻止新任务、并发断开所有设备并等待完成；I/O 线程停止后窗口才关闭。项目切换仍须先关闭工作窗口。首版不自动重连或重放写入。
