# R3 请求调度与采样质量

## 目标与依赖

依赖 R2。让多组不连续点位持续刷新，并能在轮询期间执行手动请求。

## 调度规则

- 每个连接一个串行执行器，多轮询组有独立周期和启停状态。
- 手动读写优先于尚未开始的轮询，但设置公平性上限，避免轮询永久饥饿。
- 已发出的请求不为插队取消；超时或停止后不补发积压周期。
- 先实现不合并地址的正确版本，再在同协议/同数据区及长度限制内合并连续读取。
- 排队有上限；界面显示队列满，禁止静默丢弃手动写入。

## 数据与状态

Sample 独立保存 point_id、raw_value、采样时间、最后成功时间、质量及来源 request_id。质量分为未采样、有效、超时、断开、协议失败、过期；保留最后成功值并明确标记。周期表示目标触发间隔，执行耗时单独统计。

## 实现

把 Session 中持续占用 `_task` 的轮询循环拆成调度器与单次请求执行器。统一命令 ID、取消与断开清理；Qt 通过事件批量更新采样，避免每个值都重置整表。

## 验收

两组不同周期同时工作；轮询中手动写入能执行；慢响应不积压；一组超时不停止其他组；断开后队列释放且旧结果不覆盖新连接。使用可控时钟/假适配器测试公平性、取消和状态，不靠长时间 sleep。

## 实施设计（2026-11-07）

分支 `codex/r3-scheduling`，基于 R2 `925eca8`。保留 R1、R2 分支，不合并或推送。

### 调度边界

`application/scheduling.py` 为无 I/O 的选择器，注入单调时钟。最多接收 32 个手动任务（含执行中的任务），最多 64 个轮询组；整表属于一个手动任务，其内部按请求边界让出执行权。超限发出明确的 OperationRejected，未入队、未发送，界面显示原因。

手动任务 FIFO，每个请求完成后将整表剩余部分排回队尾。已到期的轮询组按请求轮转；连续最多 3 个手动请求后必须执行一个到期轮询请求。每组同一时刻最多有一轮，完成后跳至下一个未来周期槽，遗漏周期不补发。

Session 的快速读写、快速轮询、整表读取、点表轮询共用执行器。快速轮询保留原有失败后停止行为；命名点表轮询持续运行，单组或单点错误不停止其他组。停止组移除待执行部分，已经发出的请求继续完成；断开会取消活动请求、记录未发送任务并清空全部组，不自动重放写入。

### 合并与跟踪

相邻行只有在协议目标允许时合并：Modbus 同 Unit ID、区、类型、字序且地址连续，不超过功能码数量上限；S7 同区、DB、非 Bool 类型且字节连续，不超过 200 字节。协议模型提供 merged_with，通用调度器不导入具体适配器。不跨空洞、不重新排序、不混合类型，S7 Bool 保持单点请求。

合并帧只记一条日志，每个成员值各自发出 TableReadUpdate，并关联同一 request_id。手动任务/轮询组有独立 operation_id，写入 JournalEntry；旧日志缺少该字段仍可读取。ReadUpdate 与 SessionState 带 generation，断开或重新连接后拒绝旧会话的读取事件。

### 采样与配置

`application/sampling.py` 提供 Sample、SampleStore 和 Quality。采样保存 point_id、原始值、最近尝试时间、最后成功时间、来源 request_id、generation 和错误详情。失败不抹去最后成功值；过期依据单调时间计算，只把有效样本变为过期，超时等错误保留自身质量。断开后旧值继续标记，重连成功本身不能使旧值重新有效。地址或类型改变时重置该点，删除配置时清理采样。

每张点表保存 interval_ms（200–30000，默认 1000）与 stale_after_ms（200–3600000，默认 3000）；运行启停状态不保存。项目升级到 v3，兼容 v1/v2；点表 JSON 升级到 v2，兼容 v1。老文件只在显式保存时升级。

### 界面

点表页增加周期、过期时间、本表启停、停止全部轮询和队列概览。切换表不停止后台组；轮询期间仍可提交手动读写，写入确认只核对连接身份，不因后台状态刷新失效。运行组或手动整表任务涉及的配置不可编辑；停组后允许编辑，旧地址响应不能覆盖新地址。

Qt 模型仅在配置或选表时重置；采样和过期变化以 50 ms 批量 dataChanged 更新，不重置表格或选中行。原始值、工程值、质量、最后采样及最后成功时间分别显示。多连接仍由 R4 承接。
