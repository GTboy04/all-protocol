# R1 项目文件与配置隔离

## 目标与范围

在首页新增项目操作。一个可携带的 JSON 文件保存项目名称、多条客户端设备配置（含最近查询参数及轮询间隔）、Modbus TCP 与 S7 服务端方案。打开后仅恢复配置，不连接设备、不启动监听。保留原有本地调试模式。

项目第一版仍只有一个活动客户端连接；点表、窗口布局、多连接由 R2/R4/R6 承接。设备名称初始使用端点，内部使用稳定 ID；本版通过现有设备选择器切换配置。

## 用户流程

1. 首页「新建项目」输入名称，得到空设备列表及两种协议的默认服务端方案。
2. 在客户端填写设备参数，可直接返回首页保存，无需先连接。连接/读写时也更新项目内配置。相同协议和端点合并，不同端点保留为不同设备。
3. 服务端继续编辑方案；项目模式的「应用到项目」将方案暂存到项目内存。首页保存也会收集尚未应用的方案。运行当前值不写回初始值。
4. 「保存项目」写入当前文件；首次保存选择路径。「另存为」导出独立副本并将其设为当前文件。
5. 「打开项目」读取外部文件，无需导入到本地历史；「从本地配置新建」复制本机最近连接及两种已保存服务端方案。
6. 「本地调试」返回原模式。新建、打开或切换模式前须关闭两个工作窗口，避免切换配置影响运行中的连接。未保存修改提供保存、放弃、取消。
7. 关闭项目客户端前收集有效表单；空主机跳过，非空但无效的配置提示修正。关闭服务端继续沿用应用/放弃/取消的方案处理。

## 格式与状态

扩展名 `.allprotocol.json`，UTF-8，顶层 `format=all-protocol-project`、`schema_version=1`、`name`、`devices`、`servers`。设备含 `id`、`name`、`profile`；profile 复用协议、端点、fields、interval_ms。servers 使用稳定协议键，复用既有服务端方案编码版本。项目设备 ID 在保存与更新后保持稳定。

内存状态包括当前项目、文件路径、上次保存快照。显式保存成功后更新基线；失败不得标记为已保存。保存收集所有已填入的协议表单及打开的服务端编辑方案，先完成全部校验再更新内存与文件。关闭/切换的脏检查也包括尚未应用的编辑。

## 实现划分

- `project.py`：项目模型、严格解码、设备合并、原子读写、本地配置迁移及配置存储适配器。
- `storage.py`：抽出可复用的服务端方案编解码，保留原本文件格式与日志逻辑。
- 首页：项目文件操作、未保存保护、模式选择。
- 客户端：导出当前表单配置；项目设备通过与本地历史兼容的存储接口接入。
- 服务端：允许注入项目方案存储，日志仍委托本地日志存储。

文件不包含请求日志、TX/RX、运行当前值、连接状态、自动运行任务或本机日志路径。项目操作不覆盖本地 connections.json 或已有服务端方案文件。

## 失败与兼容

- 拒绝损坏 JSON、未知顶层版本/协议、重复设备 ID/端点、非法字段类型与越界参数；错误指出配置位置。
- 限制项目文件为 10 MiB，拒绝非有限浮点；不静默丢弃坏设备。旧本地配置含坏项时整次迁移失败，不改源文件。
- 原子替换并在保存期间加文件锁；两个实例打开同一项目后检测外部修改，拒绝覆盖并建议另存为。
- 打开失败保持原项目；保存失败保留原文件及未保存状态；取消文件选择不改变当前路径。
- 本地模式继续沿用最近连接、日志与单独方案文件。

## 验收与测试

双协议设备和服务端方案往返一致；稳定设备 ID；无日志及运行值泄漏；源配置不被迁移覆盖；损坏/未知版本/非法类型/重复设备被拒绝；保存失败与外部修改保护；Qt 操作新建、保存、重开恢复且无网络行为；未保存取消保留当前状态；完整回归现有双端和存储测试。
