# R19 · 按目标设备扩展协议能力

2026-11-15 · 状态：候选规划，尚未选择首个交付项。

## 目标与依赖

依赖 R11/R12 软件基线，现有协议的现场边界由 R13 验收。本计划管理下一轮选型与立项条件，协议实现细节沿用[协议扩展开发路线](protocol-expansion.md)，不同时承诺所有候选功能。

## 候选方向

| 场景 | 候选交付 | 立项所需证据 |
|---|---|---|
| 工业网关遥测和命令联调 | MQTT 连接、订阅监视、手动发布和业务应答关联 | 可用 Broker、真实主题与载荷示例、QoS/保留约定及设备应答规范 |
| Rockwell PLC 联调 | EtherNet/IP 显式消息、标签读取、受控写入和回读 | 明确 PLC 型号、固件、路由路径及可安全读写的测试设备 |
| Modbus/S7 现有用户 | 实际需要的数据类型、地址与设备兼容性补齐 | 设备手册、脱敏报文和可复现的不兼容案例 |
| OPC UA 现有用户 | 用户身份认证、证书管理或新增节点类型 | 目标服务端与权限模型、证书生命周期，以及真实节点样例 |

## 实施流程

1. 收集具体用户场景与目标设备，先选一个能够独立验收的候选项，填写支持范围和排除范围。
2. 完成依赖库、Windows 打包、独立实现或实机互通验证；在此之前不标记为已支持。
3. 单独编写该交付项的协议语义、项目格式、点表/消息视图、诊断、写入结果及失败路径需求，再开始实现。
4. 适配现有会话身份、队列、日志、证据和资源清理；配置往返与旧项目兼容必须纳入交付。
5. 软件验收、独立实现互通、真实设备及打包版现场验收分别列状态，说明已验证的机型与限制。

## 关键边界

- MQTT 使用独立消息视图，首版不把任意载荷强行映射成点位。Broker 应答与设备业务执行结果分别呈现，后者需要应答主题和关联规则。
- EtherNet/IP 先做明确机型的显式消息标量访问，周期 I/O、完整设备模拟及未知类型留作独立需求。
- OPC UA 身份认证所需密码和私钥留在本机安全配置，不进入可移植项目、日志和报告；新增类型必须保留类型与质量语义。
- 选择现有协议补齐时不必引入新协议。跨协议网关转发、云同步和任意脚本不随本计划隐式立项。

## 立项与交付验收

- 立项前明确目标用户、设备/服务端、测试条件、最小功能范围及成功标准；缺少实机时保留预览或待验收标签。
- 完成连接、取消、断开、重复关闭、错误响应、超时和资源释放验证，覆盖适用的未知写入语义。
- 配置、项目、导入导出和报告一致；实际无法捕获的报文或业务执行证据不能伪造。
- 交付后更新协议扩展路线、需求索引、使用指南和现场支持矩阵。
