# R9 写入回读验证

## 目标与依赖

依赖 R3、R4。用户可选择写后回读，明确区分设备应答与值验证。

## 流程

确认写入目标、原始值和工程值→提交写请求→记录应答→可选延迟回读→比较→呈现证据。写入已应答、已拒绝、结果未知与回读一致、不一致、无法验证分开显示。

## 规则

- 未知结果不得自动重发；用户主动核对时执行独立读取。
- 整数和 Bool 精确比较，浮点使用明确可配置的绝对/相对容差。
- 工程值写入需反向转换，scale 为 0 时禁止，整数不得静默截断。
- 验证读关联原写请求，并在队列内保持定义好的相邻顺序；不承诺设备值在验证前不会被外部修改。
- I/IR/DI 等只读规则继续由协议适配器执行。

## 实现与失败

新增 WriteResult / VerificationResult，保留原始应答、回读时间和值；不靠日志文案反推状态。断开、取消、回读超时只终止验证，不改变已发生写入的事实。

## 验收

覆盖一致、不一致、写拒绝、写超时但实际成功、回读超时、浮点容差和倍率反算；任何路径不重复写。Qt 界面能独立说明应答结果和验证结果。

## 交付记录

2026-11-10 · 已完成。分支 `codex/r9-write-verification` 基于 R8 验收提交 `0a9feee`。

- Modbus TCP 和 S7 的快速写入与点表写入共用确认界面。点表可按原始值或工程值输入，确认前显示反算后的协议原始值和工程值。倍率为零、反算不能精确表示为整数或超出协议类型范围时拒绝相应输入。
- 自动回读由用户勾选，在收到有效写应答后执行，可延迟 0–5000 ms。写入和自动回读相邻占用同一设备的一个队列任务，其他设备可继续采样。外部设备或服务端场景仍可能在这段时间修改值。
- 浮点比较使用实际编码后的预期原始值，绝对和相对容差默认均为 `1e-6`，可在写入确认时分别设置。整数和 Bool 精确比较。用户可以核对最近或日志中所选的已应答或结果未知写入，独立读取原目标，即使相同设备重新连接后也可关联原会话。
- `WriteResult` 和 `VerificationResult` 随客户端日志保存。写应答和回读状态分别展示，日志保留原始应答、回读时间、预期值、实际值和不一致项。断线、取消和回读超时保留原写入结果，旧日志仍可读取。
- 全量 233 项测试通过，含 17 项 R9 专项。使用真实 Modbus TCP 和 S7 连接覆盖写拒绝、写超时但值已更新、独立回读、回读超时和连续请求顺序。Qt 用例覆盖工程值预览、分别展示两种结果，以及切换项目设备后恢复对应证据。
