# 工业协议调试台 V1 开发文档

2026-11-04 · 开发设计稿 · [桌面客户端界面草稿](v1-client-draft.html)

## 1. 目标与范围

在 Windows 上连接外部 Modbus TCP 设备或网关，按站号和区域读取原始值，向允许写入的区域发送明确的写请求，并通过请求日志定位故障。典型用户是现场调试人员和联调工程师。

- V1 提供一个活动 TCP 连接。用户可在同一连接上切换 Unit ID、区域和地址，进行单次读取、单点或连续多点写入，以及对一组地址定时读取。
- 会话内保留读取结果和请求日志。应用退出时释放连接。首版使用外部设备或独立测试服务端验收。
- 模拟服务端、Modbus RTU、OPC UA、多连接、常驻任务、项目保存、浮点与字序转换列为后续版本。

## 2. 技术选型与目录

采用 Python 3.12、PySide6 Widgets 和 PyModbus。用 Qt 的表格模型呈现结果和日志，用独立的 `asyncio` 线程执行协议 I/O。V1 以单进程桌面应用交付。依赖版本在首次完成连接、收发和打包验证后固定，由 `pyproject.toml` 和锁文件记录。开发入口为 `python -m all_protocol`，Windows 发布包以无 Python 环境的机器为验证目标。 [Qt 线程与 QObject](https://doc.qt.io/qtforpython-6/overviews/qtdoc-threads-qobject.html) · [PyModbus 客户端](https://pymodbus.readthedocs.io/en/stable/source/client.html)

以下为计划中的源码目录。

```text
src/all_protocol/
  __main__.py                启动入口、依赖组装和适配器注册
  application/
    contracts.py             会话接口、能力描述、请求结果与错误
    session.py               连接生命周期、请求串行和轮询
  adapters/
    modbus_tcp/
      model.py               TCP 配置、Unit ID、区域和地址校验
      client.py              PyModbus 调用、响应转换和报文追踪
  ui/
    main_window.py           窗口布局、交互状态和表格
    modbus_tcp_form.py       TCP 连接与 Modbus 点位表单
    io_bridge.py             Qt 和 asyncio 之间的命令与事件
tests/
  unit/                      规则、适配器映射与会话调度
  integration/               TCP 请求与异常响应
docs/
```

依赖方向为 `UI → 应用层接口 ← 协议适配器`。`__main__.py` 把适配器工厂及其界面表单登记到协议选择器。应用层可以在无 Qt 环境下测试，PyModbus 的对象和异常在适配器内部转换。

## 3. 协议接入契约

| 契约 | 实现约定 |
|---|---|
| 协议登记 | 稳定标识 `modbus-tcp`、显示名称、能力集合（读取、写入）、客户端工厂。协议表单由 UI 单独登记。 |
| 连接与点位 | 适配器定义有类型的连接配置和目标。V1 为 `ModbusTcpConfig(host, port, timeout_ms)` 和 `ModbusTarget(unit_id, area, offset, count)`。应用层用泛型接口传递目标。 |
| 客户端会话 | `connect()`、`close()`、`read(target)`。`write(target, values)` 通过可写能力提供。工厂以已校验的连接配置创建会话。 |
| 读取结果 | 返回有序数据项，包含适配器生成的地址标签、原始值和读取时间。日志关联请求 ID、操作、目标摘要、耗时和结果。 |
| 错误 | 统一分类为输入错误、连接失败、超时、连接中断、协议异常和响应无效。保留原始协议异常码与诊断详情。写入另外标记已确认、已拒绝或结果未知。 |

**新增协议的路径。** 为协议定义配置和目标，提供适配器和 Qt 表单，然后在启动入口注册。Modbus RTU 可在实现时提取和复用现有区域、寄存器和功能码规则，连接参数改为串口配置。OPC UA 的表单与目标可采用端点及 `NodeId`，应用层继续复用会话、结果和日志。未来的模拟服务端采用独立的监听与点位管理接口，可以复用协议地址规则。 [OPC UA NodeId](https://reference.opcfoundation.org/specs/OPC-10000-3/8.2)

## 4. Modbus TCP 实现规则

| 区域 | 读取功能码及数量 | 写入功能码及数量 | 写入值 |
|---|---|---|---|
| HR 保持寄存器 | `0x03`，1–125 | `0x06` 单点，`0x10` 多点 2–123 | 0–65535 |
| IR 输入寄存器 | `0x04`，1–125 | 只读 | |
| Coil 线圈 | `0x01`，1–2000 | `0x05` 单点，`0x0F` 多点 2–1968 | 0 或 1 |
| DI 离散输入 | `0x02`，1–2000 | 只读 | |

- 默认端口 `502`，有效范围 `1–65535`。连接和请求超时默认 `3000 ms`，界面允许 `100–30000 ms`。地址输入为十进制 PDU 偏移 `0–65535`，校验 `offset + count - 1 ≤ 65535`。按常见参考编号约定，`40001` 对应 HR 偏移 `0`。
- Unit ID 属于每次请求，允许输入 `1–255`，界面初始值 `1`，用户按设备手册调整。网关后的串口设备通常使用 `1–247`，TCP 直连实现指南推荐 `255`。V1 不开放 Unit ID `0`，避免与串口网关的广播语义混用。
- 写入数量必须等于值的数量。写入弹窗展示目标设备、Unit ID、区域、地址范围和新值，确认后才发送。成功回执显示“设备已应答”，实际值可通过再次读取核对。
- 读取结果显示位值或无符号 16 位值。十六进制是显示格式。线圈和离散输入只展示请求数量内的位，忽略尾部填充。寄存器数量不匹配、无法解析的响应作为响应无效处理。

[Modbus 应用协议规范](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf) · [Modbus TCP 实现指南](https://www.modbus.org/file/secure/messagingimplementationguide.pdf)

## 5. 会话、轮询和日志

1. **连接。** 状态依次为未连接、连接中、已连接、断开中。连接失败或意外断开回到未连接并显示原因。连接参数在会话期间锁定，站号和点位可在空闲时切换。连接成功只表示 TCP 已建立，首次成功读取才证明目标站号和地址可访问。
2. **请求。** 每个连接最多一个在途请求。手动操作忙碌时禁用重复提交。提交时冻结目标和值，用会话标识和请求 ID 关联回包，避免断开或切换查询后旧结果覆盖当前查询。
3. **轮询。** 默认 `1000 ms`，最小 `200 ms`。从本次读取结束后开始等待间隔。轮询期间锁定查询字段和写入按钮，停止后允许修改目标。遇到失败停止轮询，保留最后一次成功值并标为旧数据。
4. **超时和断开。** 首版关闭库自动重试和自动重连，并以测试确认锁定版本的行为。写请求已发送但缺少有效确认时，记录“写入结果未知”。断开或退出时停止轮询、关闭连接、等待后台退出。若此时有在途写入，保留其未知状态。 [PyModbus 客户端参数](https://pymodbus.readthedocs.io/en/stable/source/client.html)
5. **日志。** 最近 500 条请求或连接事件按时间显示。选择某条请求可展开 TX/RX 十六进制片段和异常详情。通过适配器追踪接口采集字节并原样返回，按实际接收片段记录。请求概要携带目标、功能码和耗时，便于定位问题。

## 6. 界面设计与交互

面向桌面鼠标和键盘操作。主窗体用浅灰蓝工作区 `#E9EFF4`、白色表面 `#FFFFFF` 和墨蓝文字 `#182A3D`。`#12618A` 用于主要操作，`#14745C` 标示连接或成功，`#9A4E16` 提示写入或旧值。中文使用微软雅黑，地址和报文使用等宽字。字段左对齐，数值列右对齐，状态颜色同时配文字。

```text
┌ 工业协议调试台                         已连接 · 127.0.0.1:1502 ┐
│ 协议 / 主机 / 端口 / 超时                              断开连接 │
├─────────────────────────────────────────────────────────────────┤
│ Unit ID / 数据区 / 起始偏移 / 数量          读取  写入…  轮询   │
│ 当前区域权限和功能码                                             │
├ 读取结果 ──────────────── 站号、范围、更新时间 ──────────────────┤
│ 地址                                      十进制值      十六进制 │
├ 请求日志 ────────────────────────── 选择记录后查看收发字节 ─────┤
│ 时间          目标             功能码             耗时      结果 │
└─────────────────────────────────────────────────────────────────┘
```

草稿把区域权限放在**查询字段和结果之间**，切到 IR 或 DI 时立即显示只读并禁用写入。连接区和查询区分别处理连接目标与点位目标。结果区标题保留产生这批数据时的站号和地址范围，切换查询时清空旧结果，读取失败时将同一查询的最后成功值标为旧数据。底部日志可用 `QSplitter` 调节高度，主结果表优先占用剩余空间。窄窗口将字段与操作按钮分行。断开状态显示“先连接设备，再读取点位”，已连接但无结果时显示“选择数据区和地址后点击读取”。

[打开界面草稿](v1-client-draft.html)。草稿使用示例数据演示区域切换、读写、连接和轮询的交互，预填的 `127.0.0.1:1502` 是联调示例。实际桌面实现使用 PySide6 Widgets。

## 7. 开发顺序和验收

| 阶段 | 交付和验证 |
|---|---|
| M1 · 工程骨架 | 启动入口、会话契约、协议注册、后台线程桥接和 Qt 空工作台。用测试替身验证界面可以通过通用会话发起读取并收到结果。 |
| M2 · Modbus 客户端 | 接入真实 TCP 连接、四区读取及 HR/Coil 写入。验证相同偏移在不同站号的值独立，偏移 `0` 和 `65535` 正确，读写数量上限和跨界请求正确处理。 |
| M3 · 调试工作台 | 完成轮询、写入确认、结果表和日志。验证非法地址异常、超时、断开、无效响应和界面关闭。用测试服务收到写入后故意不应答，检查客户端只发送一次并显示结果未知。 |
| M4 · 交付 | 用独立 Modbus 服务端或设备验证四区和写后读回。完成 Windows 打包，验证无 Python 环境可启动、连接并正常退出。 |

架构验收可注册一个使用字符串点位的测试协议。它应能复用会话、轮询和日志，主窗口通过注册获得它自己的表单和能力。这样能及早验证通用层未绑定站号或寄存器字段。

## 8. Git 版本管理

`main` 保存已验证的设计和实现。按开发阶段提交，每次提交对应一项可验证的改动。Windows 安装包通过 M4 验收后，从对应提交创建 `v1.0.0` 标签。发布时记录标签和依赖锁文件，以便复现该版本。
